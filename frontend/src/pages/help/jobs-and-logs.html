Jobs & logs

What happens after you press execute, and where to look when something fails.

Status

Jobs move through states such as queued, running, succeeded, or failed. The module page shows live status and log text; Home lists active and queued work so you can jump back while another page is open.

Resource queue

Host RAM and CPU limits (NEUROFLOW_RAM_MAX_PERCENT, NEUROFLOW_CPU_MAX_PERCENT) can pause new starts into a queue when the machine is busy. Wait for capacity, or finish or stop existing jobs, then start again.

On-disk layout

A typical FreeSurfer job folder looks like: 

data/jobs/freesurfer/{job_id}/
  input/       # uploaded NIfTI/DICOM
  output/      # SUBJECTS_DIR for recon-all
  meta.json    # status, parameters, command
  run.log      # merged stdout/stderr

Other tools follow the same pattern under data/jobs/<tool>/. Contents under data/ are gitignored except placeholders.

Reading the log

The UI streams the same content written to run.log. Vendor CLIs often print progress and errors there; use Official documentation for interpreting tool-specific messages.
